# Glossary

**Ability** — A concrete action the player can perform.

**Actor** — A person, organization, machine, or agent capable of participating in an interaction.

**Assumption** — A proposition treated as true without being guaranteed.

**Automation** — An executable mechanism taking responsibility for an interaction, decision, or effect.

**Automation debt** — Responsibility automated faster than the organization has retained sufficient understanding, specification, validation, or ownership.

**Capability** — A named ability a system or organization can provide through a boundary.

**Command** — An explicit request for the simulation to attempt a consequential change.

**Contract** — An agreement at a boundary about inputs, outputs, behavior, and constraints.

**Effect** — A requested interaction with the outside world or another capability.

**Episode** — A bounded sequence with entry conditions, actors, interactions, decisions, and an observable outcome.

**Event** — A meaningful completed fact in the simulation.

**Expected story** — The intended sequence/outcome based on specification or player model.

**Incident** — An observed deviation that requires explanation or recovery.

**Invariant** — A condition intended to remain true across valid behavior.

**Knowledge** — Information believed or known by an actor/organization, with provenance and confidence.

**Lens** — A UI projection emphasizing one aspect of the same underlying world.

**Observed story** — The reconstructed sequence that actually occurred.

**Pattern** — A recurring structural response to a recurring design problem; discovered through use before being named.

**Policy** — A rule guiding or constraining decisions.

**Process** — A reusable definition describing how work moves through meaningful states/interactions.

**Reality** — Authoritative simulated world behavior, which may differ from what actors or automation know.

**Scenario** — A configured world state designed to create a meaningful operating situation.

**Skill** — A domain of player/actor proficiency and understanding.

**Specification** — An explicit model of intended behavior; never assumed to be identical to reality.

**Work item** — A concrete instance moving through a process.
