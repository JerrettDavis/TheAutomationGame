# ADR-0021: Concrete Vendor Boundary Comparison

- Status: Accepted for prototype
- Date: 2026-08-12

## Context

S033 must show that outsourcing transfers work and risk rather than erasing either. A simple vendor failure would teach distrust; a single optimal package would erase the make/buy decision. The restaurant already has a rare exception, an authored economy, replayable comparisons, and a named interchangeable routing policy, so the side arc can expose a real integration boundary with measurable cost, service, support, observability, fallback, and knowledge consequences.

## Decision

Add one bounded restaurant episode with exactly three authored proposals: build in house, Sam's managed package, and Sam's observable package with a player-owned adapter. Each proposal fixes its sourcing, boundary owner, knowledge owner, support-response ticks, setup/recurring/maintenance costs, trace availability, manual fallback, and fallback labor cost.

Use one deterministic eight-request trial. At tick 3, local rare-tray code `exception` reaches an interface contracted for `special`. The package follows its contract; the mismatch is an omitted boundary mapping, not arbitrary vendor incompetence. Proposal terms determine unavailable requests, fallback work, support recovery, cost, and what local operators can observe.

`VendorOutsourcingWorld` owns selection, trial results, causal traces, and replay. Select and run are explicit commands. Every proposal remains positive-net, while normal cost, missed service, fallback labor, incident net, and organizational understanding differ. The comparison completes after two distinct proposals; no proposal is marked universally correct.

Career schema 3 persists the vendor replay alongside first shift, two-station routing, and pattern knowledge. Schema-2 careers start this optional arc empty. The Stride board pauses gameplay and projects immutable snapshots.

## Consequences

### Positive

- outsourcing is viable without being consequence-free;
- vendor behavior remains fair and causally tied to contract terms;
- cost, availability, observability, fallback, and knowledge ownership are jointly visible;
- the same incident supports an honest make/buy comparison;
- Domain and Simulation remain Stride-free and headlessly provable.

### Negative

- proposal bundles and request cadence are restaurant-specific;
- support response is modeled in abstract trial ticks rather than real-time organization scheduling;
- the episode does not yet model negotiation, renewal, lock-in exit, or a vendor relationship lifecycle.

## Validation

- reject incomplete, duplicate, or internally inconsistent proposal bundles;
- prove all three proposals remain viable and produce three distinct risk profiles;
- prove managed and observable terms change trace visibility, fallback, misses, and recovery;
- replay trials and traces exactly and round-trip them through career schema 3;
- run the headless comparison twice and compare normalized bytes;
- run two proposals through the native board, relaunch, and inspect managed/comparison/resumed frames.

## Revisit when

- a second industry needs the same contract concepts;
- negotiation, renewals, vendor exit, or portfolio selection becomes playable;
- organization-scale actors make support capacity and SLA timing authoritative;
- repeated proposal types justify a generic procurement or contract abstraction.
