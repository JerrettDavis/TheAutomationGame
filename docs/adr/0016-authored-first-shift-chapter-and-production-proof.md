# ADR-0016: Authored First-Shift Chapter and Production Proof

- Status: Accepted for prototype
- Date: 2026-08-12

## Context

The first shift had a complete mechanical arc, but its opening and report copy lived in the client, several transitions described tutorial functions rather than named coworkers, and the canonical headless completion staged clean glasses through a developer-only supply command. That combination could prove mechanics while failing to prove a coherent, independently completable chapter.

## Decision

Scenario schema-v1 may contain an optional complete chapter narrative: title, briefing pages, debrief summary, and debrief questions. The production first-shift adapter requires exactly three briefing pages and three questions to fit the existing start/report surfaces. Generic fixtures remain compatible without this optional block; an incomplete production first shift fails explicitly.

The first-shift client reads briefing and debrief presentation from compiled content. Quest situations, outcomes, discoveries, unlock rationales, guided steps, contextual barks, and immediate world notifications are revised around Avery, Ray, Jules, Tessa, and Devon's bounded incentives and knowledge. Production-facing copy no longer explains simulation/renderer boundaries, labels a debrief as a playtest, or exposes raw ticks. Detailed window-title diagnostics appear only when an automation control file or explicit developer opt-in is present.

The canonical first-shift schedule is a concrete reusable simulation proof. It uses ordinary work, demand, evidence, layout, delegation, rule-editor, replay, comparison, and shift-handoff commands. It waits for the crew to stage glass naturally before starting the live handoff. Developer supply/reset/fault commands and the legacy direct automation-policy command are forbidden by regression coverage.

## Consequences

### Positive

- the opening, quest arc, character beats, and debrief read as one workplace chapter;
- chapter copy can change through content without a client edit;
- named characters carry motives and bounded knowledge through real transitions;
- production UI no longer exposes prominent implementation/debug phrasing;
- the reference run proves the entire chapter without privileged setup.

### Negative

- scenario narrative is inline prose rather than localization keys;
- the first-shift adapter currently fixes briefing/debrief cardinality to the existing layout;
- immediate consequence notifications remain simulation-owned until a second scenario reveals a reusable authored event-message need;
- the deterministic reference schedule is a proof path, not a claim about first-time-player comprehension.

## Validation

- compile complete scenario narrative and reject missing fields/cardinality drift;
- prove briefing/report presenters consume content-only changes;
- scan authored and critical-path runtime copy for developer-language leakage;
- preserve all eight quest IDs, order, rewards, steps, and authoritative outcomes;
- complete and replay 8/8 quests with a passed live shift;
- reject developer-only command kinds from the reference command journal;
- print the complete narrative/outcome proof byte-identically headlessly.

## Revisit when

- localization replaces inline prose;
- another chapter needs a different briefing/report layout;
- human N5 sessions identify unclear beats or excessive guidance;
- a second scenario proves immediate notifications should also be fully authored.
